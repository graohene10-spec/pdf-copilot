# Codex 连接与兼容性

## 自动上下文与工具兼容

新版小助手通过实验性 `dynamicTools` / `item/tool/call` 接口登记当前 PDF 的只读工具，已在 Codex CLI 0.160.0 和登录账户上完成真实指定页读取与引用回复。最低版本检查仍为 0.159.2；注册字段接受不等价于所有未来版本都能正常执行。

真实测试发现仅登记工具但设置 `code_mode_host=false` 时，Codex 能看到工具却无法调用。本版开启这个工具通信组件，同时继续禁用代码模式、shell、执行环境、外部 MCP/插件及其他动作。主机只转发四个白名单 PDF 请求。工具执行机制可参照 [官方动态工具实现](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/dynamic.rs)。

app-server 拒绝动态工具字段时，扩展尝试兼容阅读计划：模型给出少量关键词/页码，浏览器检索并补充附近段落和页图，模型依据证据回答。此模式有额外一次请求，保留用户配置的页数/文字/图片/调用预算和引用。旧小助手不认识新增 `pdfLimits` 字段时，明确提示重新安装助手，不静默忽略资源配置。认证失败、网络失败和隔离校验失败不会被误判成工具不兼容；仍会报告错误。

## 多份 CLI 的版本与登录诊断

独立安装、npm 安装与 Codex 桌面附带的 CLI 可以同时存在。终端能找到新版，不代表小助手登记的程序已更新。以插件设置中的 **实际程序**、**CLI 版本** 和 **登录状态** 为准。

- 安装器检查已登记路径、独立安装、PATH、npm 包内部 Windows EXE、桌面附带程序及 WinGet 链接的真实版本，选择满足支持基线的最新候选。明确的 `-CodexPath` 优先且必须通过验证。
- 小助手识别合法的 prerelease/build 后缀，报告实际程序路径、版本、最低支持版本和诊断信息。数值版本检查只是初筛，聊天前仍验证服务返回的隔离条件。
- 旧版或无法连接时登录状态为“尚未确认”，不会推断为未登录。已确认未登录才显示该程序的准确登录命令。
- 图片继续以内联数据传输；协议与浏览器层没有新增截图落盘行为。

## 为什么暂时保留 0.159.2 基线

这表示当前适配器验证过的最低版本，不表示 0.159.2 才首次引入全部相关字段。

实际生成的 0.149.1 schema 已含 `thread/start.ephemeral`、`thread/start.environments` 和 `turn/start.environments`，且描述明确说明空数组禁用执行环境。但该 schema 未包含当前适配器使用的 `thread/unsubscribe`，旧版本完整回收与工具隔离流程尚未验证，单凭字段存在不足以保证兼容。

当前适配器要求临时会话、只读沙箱、禁止审批、关闭网络和空执行环境，禁用继承的工具、MCP、插件与指令，并检查返回的临时会话/沙箱条件。不能为了放宽版本而降级为普通持久会话、把截图写成临时图片或放开执行环境。官方 app-server 区分稳定与实验接口，需要对实验字段主动启用能力；采用这些字段的适配器仍应验证真实协议行为。[官方协议文档](https://learn.chatgpt.com/docs/app-server)

## 可选方案

| 方案 | 兼容性与代价 | 建议 |
|---|---|---|
| 保留 Native Messaging + Codex app-server | 沿用 Codex 管理的认证；有 CLI 协议依赖，安装器提供选路、版本解析与诊断 | 当前默认方案 |
| 按协议能力与已验证版本矩阵选择适配器 | 比单纯版本门槛更灵活；要为旧版本验证临时会话、无执行环境、取消、图片输入和回收 | 后续兼容旧 CLI 的首选方式 |
| 扩展直接使用 OpenAI/DeepSeek API Key | 已支持；不依赖 CLI、Windows 助手或其版本。需要用户提供 API Key，不能直接复用 Codex 认证 | 想减少本机依赖时使用 |
| 改为 `codex exec` 或提取桌面登录令牌 | 前者还要重验工具隔离、图片与回收；后者依赖桌面内部实现和凭据格式 | 不采用 |

能力适配应先在开发阶段对官方生成的 schema 和真实版本进行验证，再由运行时检查服务返回条件。不能用“服务器没有报未知字段”作为能力证明，因为旧实现可能忽略未知字段。当前修补版未宣称支持未验证的旧协议。

改善登录体验可后续增加官方 `account/login/start` 浏览器或设备码流程，由 Codex 管理登录，并在断开时取消。这样用户能在设置页发起登录，无需手动寻找终端；它解决操作体验，不消除 CLI 版本依赖。当前仍使用该可执行文件的 `login` 命令。[官方认证流程](https://learn.chatgpt.com/docs/app-server#authentication)

## 更新既有安装

1. 保存解压后的新包，关闭旧设置页和聊天窗口。
2. 在扩展管理页更新或重新加载新 `extension` 文件夹；开发扩展 ID 保持不变。
3. 运行新包 `windows-helper/install.cmd`。若用商店 ID，按安装说明传入实际 ID。
4. 打开设置页检查连接；按显示的真实路径执行登录命令，然后再次检查。

安装器重新登记时只登记本次参数中的扩展 ID；使用自定义 Edge/Chrome 商店 ID 时应一并传入，避免丢失原授权。

官方 [CLI 安装文档](https://learn.chatgpt.com/docs/codex/cli) 和 [版本记录](https://learn.chatgpt.com/docs/changelog) 是获取更新的依据。独立 CLI 与桌面附带 CLI 可以同时存在；小助手实际登记的路径才决定它调用哪一份。
