# 开发版：框选快捷键、多标签页与排队

日期：2026-10-09。基于 v0.3.3 的本地开发改动，未创建新的 GitHub 发行版。

## 实现

- 复用浏览器 Commands 中的 `capture-region`，默认 Alt + Shift + S，已自定义的组合继续有效。增强模式发送给原阅读器并进入框选；原生模式仍截取可见标签页并打开裁剪窗口。只有四项默认组合，避免超出 Chromium 的默认快捷键数量限制。
- 保留窗口级全局侧栏。每个标签页和 PDF 指纹分别保存消息、附件、草稿、模型和思考强度；请求回调只更新所属会话，当前显示的会话可以随标签页切换。临时窗口继续绑定原标签页。
- `common/request-queue.mjs` 提供可独立测试的有界调度；`request-broker.mjs` 在服务工作线程中串行协调所有窗口；`chat/request-ticket.mjs` 管理启动名额、通知、取消和丢失通知的恢复。后台不承担模型流，也无需新增 offscreen 权限或依赖。
- 默认总并发 2、Codex 并发 1、等待 8。设置范围分别为 1–4、1–2、0–16。优先启动最早的可运行提问，避免被 Codex 专用名额堵住其他服务。降低上限保留已经运行的回答，新增启动遵守新上限。
- 模型、强度、文档页码、资源预算和手动附件在发送时确定；增强 PDF 等获得名额后才创建读取会话，避免队列耗尽文档连接。原生可见图片在等待前固定，切走过早会拒绝错误来源截图。
- 后台只保存随机请求编号、所属对话身份、标签页、服务商和调度状态。Chrome 提供消息文档 ID 时使用文档 ID；Edge 侧栏缺失该字段时使用随机内存身份及存活应答。关闭界面释放名额；工作线程重启可识别仍存活的流，不重复启动。存活扫描在全局合并，避免每个客户端重复扫描所有对话。
- PDF 导出图片使用 PDF.js 的 print 渲染调度，绕开隐藏页的 requestAnimationFrame 暂停；阅读器的屏幕渲染保持原流程。原生 PDF 的页码 fragment 共享会话，不误当作换文件。

多标签页测试覆盖：会话/草稿/模型强度隔离、两路实际 HTTP 流同时运行、排队页码和预算锁定、队列满恢复问题、提交准备时立即切走、排队取消不调用模型、停止实际 HTTP 流、后台工作线程重启、临时窗口共享上限及关闭释放、关闭后台原 PDF、原生 PDF 页码跳转、排队可见图固定、快捷键命令分发后实际鼠标拖动并出现截图预览，以及调度存储不包含问题/回复/图片。

后台文字与页图测试会让原 PDF 处于非活动标签页，再显式暂停它的动画帧，验证按需读取和页图仍完成、证据只回到原会话。无头 Edge 可将非活动标签页报告为 visible，因此不能把该报告当作桌面可见性结论。

测试使用合成 PDF 和本机模拟接口，没有调用真实付费模型。无头测试无法触发操作系统级快捷键：测试检查浏览器真实注册的组合，再调用实际命令监听器并拖动鼠标；用户真实键盘与冲突改键仍由浏览器管理。没有声称已在 Chrome 上做相同实机验收。

## 使用边界

切换标签页继续接收；关闭侧栏/临时窗口、关闭原 PDF、在原页更换文件或重载增强阅读器，停止对应提问。原生同网址刷新和页码跳转可保留已固定截图的回答。浏览器重启或重新加载插件不恢复内存聊天。会话缓存只保留有限数量的闲置文档，运行和等待中的会话不会被清除。

默认与极简版的分发行为相同；本次无需更新 Windows 小助手。
