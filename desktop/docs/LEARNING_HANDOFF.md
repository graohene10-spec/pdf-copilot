# 交接：`learning-mode-design` 分支

写给一直维护主线的那个会话。这个分支是另一个本地会话在 2026-11-25 到 26 两天里做的，基于 `a712432`（main，0.10.147）。
没有合并，没有发版，没有改版本号和发布说明。合不合、怎么合，由你和用户定。

设计思路在 [LEARNING_MODE_DESIGN.md](LEARNING_MODE_DESIGN.md)。那份文档写在动手之前，后来用户改了不少要求，**以本文和代码为准**，对不上的地方见第 5 节。

## 1. 这个分支里有什么

| 内容 | 一句话 |
| --- | --- |
| 学习对话 | 阅读助手里和"总结"并列的第二种带任务的对话：摸底 → 大纲 → 一步步带读，每步链回原书 |
| 大纲栏 | 学习对话的一栏，可放在助手栏左侧或屏幕最左，节点能右键、拖动、删除 |
| 学习进度页 | 左侧栏原来的"Intelligent UI"入口换成它，列出所有学习对话 |
| 学过的要点 | 通过检查的节点存进"设置 → 记忆"里那本书下面 |
| 教程 | 新增两段（学习、大纲与进度），核对并修补了原有 15 段 |
| 四处和学习无关的改动 | 见第 3 节，**都动了主线的行为，请逐条看** |

## 2. 学习对话怎么接进来的

照"总结对话"的先例做，没有改 Rust，没有加 sdk 方法。

**状态**

- `ChatState.learning?: LearningState`、`Message.learn?: LearnAnswer[]`（`src/ai/workspace.ts`），跟着对话一起存。
- 状态机是纯函数，在 `src/ai/learning.ts`：无 import，可直接单测（`tests/learning.test.mjs`，68 项）。这个文件的主体是本机 Codex（gpt-6.2-astra）写的，Opus 审过一轮、返修过一轮。
- 助手用四种带标记的代码块和应用说话：`learn-quiz`、`learn-plan`、`learn-level`、`learn-mark`，内容是 JSON，本地解析。**没有用工具调用**：Codex 的工具清单写死在 C# 宿主里，加工具要发版；现有的 ` ```ui `、`<summary-doc>` 也是这个路数。
- `src/ai/learning-normalize.ts` 在解析前把模型写歪的块扶正。三种情况都是实测遇到的：DeepSeek 把块写成 `<｜DSML｜invoke …>` 工具调用语法；JSON 里的 LaTeX 只写一个反斜杠；把历史消息里的 `[此前查到的相关位置]` 抄到回答末尾。

**`sendChat` 里的分支**（都在 `workspace.ts`）

- 系统提示词换成 `learningInstructions(...)`（`src/ai/learning-prompts.ts`，按阶段换），带读阶段另加 `UI_INSTRUCTIONS.assistant`。
- 每次请求在问题后面附一段 `[学习进度]`（`learningContext`）：大纲、各节点状态、快讲细讲标记。所以压缩和 200 条消息的裁剪都不会让助手忘了讲到哪。
- 回答写完后调 `advanceLearning` 推进状态；格式有误或该规划路线了，`followUp` 返回一句话，应用替读者补发（`auto: true`，和总结的"继续"走同一条路，原来的 `again` 变量改成了 `next`）。
- 不带当前页图（和总结一样）。

**读者直接改大纲不经过助手**：`editPlan(documentId, conversationId, edit)` 本地改 `state.learning.plan`（删节点、标快讲细讲、换次序），助手下一问时从 `[学习进度]` 里看到。

**新的存储 key**（都在 settings 表）

| key | 内容 |
| --- | --- |
| `learn.map.v1.<documentId>` | 这本书学过的要点 |
| `learn.map.books.v1` | 哪些书有要点 |
| `learn.sessions.v1` | 所有学习对话的名册（学习进度页和文档库卡片的进度条读它） |

名册是后加的：第一次启动时没有这个 key，`App.vue` 会调一次 `allConversations(全部文档)` 把已有的对话读一遍补上。**文档库很大时这一下可能慢，没有实测过。**

localStorage 新增 `kaizhi.learn.outline.side`、`kaizhi.learn.outline.width`。

## 3. 和学习无关、但动了主线行为的四处

**3.1 自动压缩默认值 40K → 200K，并加了窗口上限**

- `src/settings/model.ts`、`src/ai/compaction.ts`：默认 `compactK` 改成 200。
- 新增 `limitFor(window) = min(设置值, 模型窗口 × 0.6)`，`sendChat` 里触发压缩、裁历史、`historyTokens` 都改用它；`AiPane` 里圆环的上限也用它。原来的代码完全不看模型窗口，直接设 200K 会让 DeepSeek（128K）的历史本身就超窗。
- 0.6 这个系数是拍的，没有按各家的输出上限细算。
- 已存过偏好的老用户不受默认值影响（偏好整份保存）。

**3.2 上下文圆环的悬停提示改短**

`上下文 12k / 40k tokens，满了自动压缩，点击立即压缩` → `上下文 12k / 40k，点击压缩`；`正在压缩对话` → `压缩中`。用户嫌原来的过度解释。

**3.3 附属对话展开动画**（`App.vue` 的 `setPanelSide`、`AiPane.vue` 的 `holdMain` / `whenSettled` / `side-col`）

原来展开时主栏、Markdown 正文、新挂上的附属对话每帧都在重排。现在沿用助手栏开合的办法：动画期间定住正文和主栏宽度，附属栏不再自己做宽度过渡，内容等窗口停下再填。无头 Edge 实测主栏重排次数从 7–11 次降到 0。**没在 WebView2 和真实显卡上看过。**

**3.4 Codex 宿主要思考摘要**（`native-host/CodexClient.cs`，两处各加一项 `model_reasoning_summary="detailed"`）

用户反映用 astra + max 时等一两分钟界面毫无动静。原因：宿主会转发 `item/reasoning/summaryTextDelta`，但从不要求 Codex 发摘要，astra 默认不发。实测改后第 35 秒收到第一条思考事件（改前要等到回答开始）。编译和自检通过。**需要重新发版宿主才生效；摘要只有一两条短标题，总耗时不变。**

## 4. 左侧栏的 Intelligent UI 入口

用户要求把它换成"学习进度"。`App.vue` 里那颗按钮现在是 `chooseCategory('learn')`。**`UiCollection.vue` 和 `category === 'ui'` 的代码都还在，只是没有入口了。** 是彻底删掉还是换个地方放，用户还没定。教程里演示合集的那一步已经删了。

## 5. 和设计文档对不上的地方

设计文档是动手前写的，下面这些以代码为准：

- **摸底**：文档写一题一轮；现在是每轮两道题、一起提交（用户嫌一题一轮太慢）。
- **路线图**：文档写助手栏顶部一条可折叠的带子；现在是独立的大纲栏，可放两个位置、可拖宽。
- **规划原则**：文档写"最小路线，已掌握的不放进去"；现在是"覆盖范围内原文的全部要点，不跳出原文，已掌握的一步带过"（用户要求兼顾广度和深度）。
- **目标**：现在有三种预设学法（速通、复习、深度理解），写在 `LEARNING_GOALS` 里，会改变助手的做法。
- **节点**：多了 `pace?: 'fast' | 'slow'`；显示次序就是 `plan.nodes` 的次序，不再按依赖做拓扑排序。
- **调整大纲**：文档写"第一版只能用文字"；现在右键、拖动、减号都是本地直接改。
- 文档第 7 节的"阅读预算实测"**没有做**，见下。

## 6. 验证到什么程度

- `npx vue-tsc --noEmit` 0 错误；`node --test tests/*.test.mjs` 232 通过（原有 163 + 学习 68 + 压缩上限 1）。
- `scripts/outline-check.mjs`：不调模型，塞一份假状态，验证右键标细讲、拖动换次序、减号删除。
- `scripts/learning-trial.mjs`：用真模型走一遍学习对话（`KZ_KEY=<DeepSeek key> node scripts/learning-trial.mjs`）。用 `deepseek-flash` 跑过十来遍，其中一遍从摸底走到全部节点通过（19 次请求，输入约 20 万 token）。
- **全部验证都在浏览器预览里做的**（`npm run dev`，数据在 IndexedDB）。本机没有 Rust 工具链，**桌面版一次都没跑过**。所以：
  - Codex 路径下的学习对话没测过（设计上不依赖新工具，理论上能用）。
  - 真实 PDF 没测过，试跑用的是一篇七节的 Markdown。翻页多的教材每步要读多少原文、花多少 token，没有数据。现在学习对话用的是默认的文档阅读预算。
- 只在 DeepSeek 上跑过。其他服务商写这四种块稳不稳，不知道。
- 三种学法里只实跑过"深度理解"。
- 大纲栏在暖色和玻璃风格下没有截图看过。

## 7. 已知的问题

按影响大小排：

1. **复制助手的回答会把题目的 JSON 连同答案一起复制出去。**
2. **大纲在屏幕左边时关掉整个助手栏，大纲瞬间消失**，阅读区跳 274px。大纲由 `AiPane` 管，助手栏一卸载就来不及播退场动画。要修得把大纲从 `AiPane` 里拿出来。
3. **大纲在助手栏里时，拖宽度的抓手被 `.panel-resizer` 盖住**，基本抓不到。
4. 调整模式里拖动节点，被拖的那个是跳到新位置的，不跟着指针连续移动。
5. "跳过"一道题在界面上没有入口，`learning.ts` 里相关的分支走不到。
6. 多栏并排时，`App.vue` 的 `jump` 作用在当前激活的阅读器上，引用和大纲节点可能跳到另一本书。这是原有问题，学习让它更显眼。
7. settings 表单值上限 1 MiB、超了静默存不进去（`db.rs`）。学习对话消息多、每条带 `sources`，更容易撞到。原有问题，没处理。
8. `docs/PRIVACY.md` 还没写学习记录和要点存在本机这件事。

## 8. 用户的口味

这两天用户反复提的几条，写在这里省得你再踩：

- **不要过度解释。** 界面上的字只说读者此刻需要的那一点，不讲机制，不预告流程。
- **动画不能瞬移。** 面板开合、换位置都要和已有的面板一样是连续的。
- **要跟主题。** 新界面用主题自己的字体、颜色、圆角。唯一的例外是题目卡片：用户明确要求实心底加正文字体，因为透明底看不清。
- **不要一次一道题那种慢节奏。**

## 9. 教程

教程从 15 段变成 17 段，四个 Opus 子代理做的：两个各加一段，一个核对原有 15 段，一个总验收。

**新增**

- 第 06 段「学习」：`src/tour/lesson-learn.ts`、`src/tour/TourLearn.vue`。设定表 → 摸底两题一起交 → 大纲、点"就这样开始" → 带读一个节点。
- 第 07 段「大纲与进度」：`src/tour/lesson-outline.ts`、`src/tour/TourOutline.vue`（Scene 字段叫 `plan`，因为 `outline` 已经被"阅读视图"的目录面板占了）。文档库卡片上的学习进度 → 学习进度页 → 右键节点 → 调整模式拖动和删除 → 写一句话让助手改 → 挪到屏幕左边。39 秒，是最长的一段。
- 依赖方向是 `lessons → lesson-outline → lesson-learn`，没有环。

**原有 15 段里改了什么**

- 「用图解释」删了第 3 步（进 Intelligent UI 合集），`steps` 3 → 2。假界面里的合集视图、`'collection'` 这个 view 值、相关样式都删了；侧栏那一行的类名 `.tw-nav-ui` 改成 `.tw-nav-learn`。
- 文案治理那次 WIP 漏改到教程的 4 处旧文案补上了："已填密钥""…或已索引内容""助手正在看这些记忆，按你说的改…""改好了：改写 1 条，去掉 1 条"。翻译开关"自动翻译"改成真实的"划词翻译"并挪到翻译栏底部。段名"文库"改成"文档库"。
- 假欢迎页原来画的两颗胶囊（"总结这一页""这个公式怎么来的"）真实界面里没有，换成现在的"总结这份文档""学习这一段"。指令列表加了 `/learn`、`/outline`。
- 「阅读助手」分支之后：去掉了"分支"小标签和一条说明用的虚线（真实界面没有），改成标题显示"… · 分支"、附属栏收起。
- 「截图提问」`steps` 9 → 10（字幕本来就有 10 句）。「外观」切深浅色那一步改成先关设置窗再点月亮（真实的设置窗是模态的）。
- 缩短了二十多条字幕。
- 修了十几处瞬间跳变：模型下拉菜单、解释卡片里的图、展开小节、截图那排缩略图、并排阅读的第一页等，都改成有过渡。`TourPlayer.vue` 的复位和开场摆状态不再走过渡，摆好了再揭开画面。

**验收结果**

- 17 段的 `steps` 都和字幕条数一致。草稿浅色下每段循环两遍，第二遍复位干净。
- 生产构建（`vite build`，输出到仓库外）成功，`vite preview` 里 17 段逐段播完，没有报错。
- 完整跑过 17 段的组合：sketch 浅、glass 浅、crystal 深、warm 深、glass 1100×720。其余组合只跑了新加的两段。小窗只看了新加的两段。

**没修的**

1. 「管理对话」拖放和撤销时，对话行是一下重排的（被拖的那条跳 118px）。要平滑得给两层都做 FLIP。
2. 「标记」拿起笔和退出时，顶部工具条宽度一下变 54px。
3. 系统开了"减少动态效果"时，教程里的展开和滑出会直接出现，但镜头推拉和光标移动照常。要不要这时也停掉镜头，用户没定。
4. 「大纲与进度」右边对话区显示的是第 1 个节点的讲解，而大纲停在第 3 个节点，只做到大致衔接。
5. 没演示的：`/outline` 指令、"重新设计"按钮、右键菜单的"删掉"和"恢复正常"、学习进度卡片的删除确认、拖动大纲宽度。
